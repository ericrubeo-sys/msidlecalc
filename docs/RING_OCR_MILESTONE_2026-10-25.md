## Minimum and Advanced questions

No numeric character value is universally essential. Complete proved cancellations/dominance can need none; unknown mechanics cannot be repaired by a generic stat sheet. For supported changed effects only, the current model conditionally consumes:

| Basic question | Implemented consumer / necessity |
| --- | --- |
| Current character Attack, points | Bounds the response of changed upper/lower Attack sources under `A=B+gQ`, `B>=0`, provisional `g>=1`; unnecessary when the zero-question proof resolves the whole admitted comparison. Current total alone is not an exact source inverse. |
| Current Critical Rate and full Critical Damage, % | Explicit critical/noncritical event expectation, with provisional `p=clamp((R-resistance)/100,0,1)` and the multiplier inside each content transform. Asked only for supported changed critical sources. |
| Current total of a changed applicable damage bucket, % | Additive bucket replacement across coherent source-display scenarios; unchanged or context-irrelevant buckets cancel only within the admitted model. |
| Shared slot stars | Known Main/Sub amplification lookup12–30, automatically read from matching headers where possible. Never require retyping the two12-star headers. |

Read totals in Character with the **current** item equipped. The candidate never needs to be owned or equipped. There is no activity selection. For the complete ring, none of these new questions is shown because changed Main Stat/skills/range block the calculation first; previous entries remain retained.

One Advanced disclosure uses the same underlying supported model. It accepts both Main/Sub amplification percentages to replace the star lookup, opponent Critical Resistance to narrow admitted critical scenarios, and explicitly supplied Attack/percentage uncertainty margins. It also retains other supported totals for reuse. It does not expose speculative Main Stat weights, generic skill bonuses, unused job/level questions or a distribution selector presented as fact. No rounding margin is invented.

Numeric contract: typed item points/levels require nonnegative integers; typed percent effects normalize an optional percent suffix to an explicit percentage. Character fields accept nonnegative decimal English-form numbers, valid comma grouping and optional percent suffix only on percentage units, at most18 fractional places and at most9,007,199,254,740,991. Attack/full Critical Damage must be positive. Star lookup is integer12–30; another stage requires a complete valid Advanced amplification pair. These are software limits, not proven game maxima. Exact linear arithmetic and conservative nonlinear checks still abstain on numerical overlap, invalid reconstructed states or ties.

## Evidence and next numerical work

The mechanics specialist rechecked rendered official guide tabs and current/historical balance notes, distinguishing publication facts, deductions and assumptions. Main Stat affects both Attack and Stat Prop. Damage, so adding its whole contribution to displayed Attack would double count. Current tier effects require actual level functions and passive/trigger dependencies. Min/max endpoints do not identify a probability law; changing the upper endpoint alone does not prove stochastic dominance. Nonlinear contexts require transforming outcomes before expectation.

No live-game measurement or prediction validation was performed. The user's replacement-only equipment UI makes empty-slot tests infeasible; ordinary swaps with several changed stats do not identify their separate responses. A→B→A can show stability but cannot remove that confounding. No new matched-pair, purchase, upgrade or candidate-equipped request is made.

Next numerical gates are: obtain current affected skill level functions and mastery conditions; establish source-aware Main Stat conversion into both offensive factors; establish range/critical joint behavior or a valid distribution-free bound; then test the **whole ring** under all admitted source scenarios and activity transforms. An in-game read-only arbitrary-level preview is only a possible data lead, not assumed available or a requested irreversible experiment.
