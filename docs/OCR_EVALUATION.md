## Visible audit and resource-denial procedure

The audit bootstrap runs before the Tesseract bundle. It counts main-page Storage writes/removals/clear, IndexedDB open/delete calls, console methods, page errors/rejections and CSP violations. Console argument bodies are suppressed, not retained or forwarded. Storage inspection reports counts only: local/session entries, database count where supported, CacheStorage named-cache count (not entries inside each cache). It does not reveal key/database names or values. These probes do not instrument worker globals, browser-generated console messages or preexisting activity before page bootstrap; worker privacy also needs reviewed cacheMethod:none code, CSP, fixed-resource counts and browser inspection.

The server keeps only method-category/rejection counts, gate status and fixed-allowlist asset counters in memory. `/audit` reports those plus installed asset byte lengths/SHA256 hashes; hashes are recomputed from actual served buffers to avoid stale startup manifests after local file edits. No arbitrary request paths, query values, bodies, file names or raw OCR are recorded. Fixed local metadata identifies resources actually served, including worker-selected core variants. Counters are aggregate server-process evidence and may include other local test tabs; restarting clears them.

1. Restart server/reload; refresh audit and inspect initial storage counts. Select the permitted example and run once. Verify local resource counts, workerAlive:true, no unexpected storage/errors/CSP activity.
2. Click **Block vendor resource loads**. It makes subsequent `/vendor` reads return503; audit/gate controls remain accessible. The control does not disconnect external networking or emulate every offline browser condition.
3. Repeat using the retained worker. Record text equality/duration, unchanged vendor served counters and any blocked requests. Correct a line while the gate is blocked. A successful repeat demonstrates that this initialized worker needed no new vendor resources under this gate, not universal offline capability.
4. Cancel to release the worker, then run with the gate still blocked. A resource request should fail rather than use a CDN. Observe blocked counters and honest failure. Reopen gate to recover. Reset and verify in-memory image/text removal; storage counts should remain empty in a clean evaluation origin.

Remaining adoption gates: representative permitted varied/held-out fixtures with exact field-match numerator/denominator, browser variation, actual overlapping selection/history-navigation checks, and reviewed parser/manual integration. Keep all private raw outputs out of public artifacts. Package-lock integrity plus audit resource hashes support reproducibility, not accuracy or complete privacy certification.
