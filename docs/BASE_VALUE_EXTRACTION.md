# Base item values and displayed changes

The user's 2026-10-23 live-test correction establishes the supported comparison convention: equipped item left, candidate right. Candidate colored numbers are displayed changes. They are not a complete comparison source because a stat present only on the equipped item may have no corresponding candidate row. Recommendations must eventually compare complete, reviewed item lists. Missing recognition is unknown, not absence or zero.

`public/domain/ocr-item-rows.js` implements pure draft assembly `item-base-rows-1`. `proposePanelRows(panel)` returns `{version, method, issues, rows, evidenceRows}`. Each row has `rawText`, `proposedFields` (`rawLabel`, `rawValue`, `unit`, `comparisonText`, `issues`) and original observation evidence. Only an exact `On-Equip Effect` heading (case/space/hyphen normalization) moves to non-stat `evidenceRows`; approximate spellings and all other unknown observations remain editable. This narrowly identified section heading must not become a missing stat value. `screenshot-review-2` imports the item proposals and retains heading evidence in provenance. All imports remain unconfirmed; source, implementation and live-game confidence remain distinct.

When every structured OCR word has finite positive boxes and the words cover the raw transcript, vertical-overlap components propose visual rows. Every word in a component must mutually overlap vertically by at least 65% of the larger word height, and horizontal boxes must not overlap. This avoids chaining a tall bridging word across adjacent rows. Words are then ordered left to right. A textual label followed by exactly one complete numeric token proposes the base value. A second separated numeric token is retained only as `comparisonText`. Neither sign nor color establishes a value. Multiple complete numbers inside the label, malformed/merged numeric tokens, numeric-only fragments, unknown text and ambiguous geometry receive no proposed numeric field. Unicode and unfamiliar labels are retained without dictionary filtering. Repeated labels are never merged.

The method does not repair OCR digits, normalize numeric separators, infer missing rows, select a locale, infer a zero, or confirm a quantity. Literal commas/percent signs remain for review. A delta split by the OCR engine onto a separate text line can rejoin its actual visual row when its word box uniquely supports that association. A fragment on another vertical row stays an unknown observation. The strict geometry can abstain on otherwise legible text; correction remains necessary.

If geometry is missing/incomplete, the raw-word coverage differs from the transcript, or the word count exceeds the bounded 1,000-word limit, all original raw lines are retained through the existing text proposal path. Blank observations are retained. Spatial rows retain original structured lines, words/boxes, full raw transcript and original raw-line records in provenance. No private player text or ground truth is published in this document or the invented tests.

Verification: `tests/ocr-item-rows.test.mjs` covers split label/base/delta lines, separators/units, detached numeric fragments, unknown and Unicode labels, repeated stats, unequal lists, ambiguous bridging/overlapping geometry, lossless fallback, and imported confirmation boundaries. These are deterministic implementation tests, not an OCR accuracy estimate. The current attached images show the application rendering/transcript; they are not a new game-original evaluation fixture. Actual localization/recognition still requires representative original screenshots and private source-linked evaluation.
