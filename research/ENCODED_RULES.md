## Replacement without equipping the candidate

`public/domain/reaggregation.js` is pure and deterministic, independent of DOM, OCR, theme, storage, clock and network. Inputs must represent verified source identity/stage; a boolean assertion cannot establish missing game semantics. APIs return before/after values, claim IDs, versions and scope. They never return an equipment winner.

- `replaceAttributeSources({sources,oldSourceIds,candidateSources})`: source records `{id,stage,value}`; stages `flat`, `ordinaryMultiplier`, `skillMultiplier`, `skillFlat`. Flat records add within their supported stage. Exactly one explicitly preaggregated complete ordinary factor and one Skill factor are required, including explicit1 when neutral. Computes `(sum(flat)*ordinaryFactor)*skillFactor+sum(skillFlat)`. This does not presume different percentage-source types add. Replacing a percentage-stage record requires a verified replacement aggregate factor. It does not convert Main Stat into Attack or Stat Prop. Damage.
- `replaceFinalDamageSources({sources,oldSourceIds,candidateSources})`: records `{id,value}`, where value is an independent bonus fraction; aggregate is `product(1+value)`.
- `replaceFinalDamageFromTotal({totalMultiplier,oldBonusRate,newBonusRate,totalIsExact})`: exact full aggregate multiplier must contain the identified old independent source exactly once; new factor is `total/(1+old)*(1+new)`. Rejects rounded/unverified totals and inconsistent old-source reconstruction. This inverse is algebra derived from the published stacking rule, not a separately published equipment formula.
- `replaceRemainingCapSources({sources,oldSourceIds,candidateSources,cap})`: records `{id,value}` in absolute fractional rates, not proportions of cap. Computes `cap*(1-product(1-value/cap))`. Known unchanged sources allow replacing even a saturated old source without inventing the other contributions.
- `invertRemainingCapReplacement({total,oldSource,newSource,cap,totalIsExact})`: for verified exact independent source semantics only, reconstructs unchanged aggregate `(total-old)/(1-old/cap)` then reaggregates new. Rejects any saturated total/old source and a normalization denominator at or below1e-8. Rounded displayed totals lack a measurement-uncertainty policy, so are not admitted. Saturation rejection is intentionally conservative even where a more limited conclusion might be possible.

Source IDs are unique; missing/duplicate replacement IDs, duplicate final IDs, malformed stages, nonfinite/negative values, out-of-cap sources, arithmetic overflow and positive product underflow reject. Remaining-cap aggregation uses `log1p`/`expm1` to preserve small rates rather than cancel to zero. Final Damage bonuses below representable factor precision reject. Arithmetic uses IEEE754; it does not imitate unspecified game rounding. The1e-8 inverse guard is a technical conditioning limit, not a game cap. Existing legacy `orderedAttribute` rate arrays are safe only with separately established same-type aggregation; the new source API avoids assuming that grouping.

## Scrutiny of the proposed light inputs

Static Critical Rate plus an Accuracy confirmation is not generally enough. The smallest valid input depends on what changes and which factors can be proven common. Requiring Critical Rate universally can also be unnecessary.

| Proposed input | Formula/eligibility consumer | Essential, optional or cancellable | Missing-data consequence / extraction boundary |
| --- | --- | --- | --- |
| Every changed item line, units, source stage | Replacement and complete-effects eligibility | Essential; preserve unknown/repeated/unequal lines | Unsupported offensive change prevents complete winner. Item screenshot gives candidate lines, not their source-stage proof |
| Stable current totals or source decomposition | Marginal replacement in the affected family | Essential for changed additive bucket/Attack; verified decomposition can derive candidate | Never require an unavailable candidate equipped. Ask only the missing affected-stage aggregate/decomposition; item screenshot alone insufficient |
| Critical Rate | Effective-event expectation | Conditional; can cancel if critical branch distribution is unchanged and factor scaling/context algebra permits | No guessed cap or overflow. A displayed rate may omit resistance/eligibility; extraction is not verification |
| Critical Damage | Critical branch multiplier | Essential when changed or coupled to changed critical probability; otherwise may cancel under proven conditions | Rate alone cannot determine the value of added critical chance. Character panel required for total semantics |
| Accuracy/hit adequacy | Hit-event eligibility | Adequacy assumption can bypass numeric hit curve for the named limited output; changed/marginal hit rate needs target/Evasion rules | No universal threshold or hit-rate interpolation. Guide's100-gap/70%-evasion boundary alone insufficient |
| Current damage buckets / Final Damage | Marginal factor after proper reaggregation | Conditional on which bucket changes; unchanged multiplicative factors can cancel only with proof | Unknown aggregate blocks a bucket's percentage-value comparison; preserve other supported partial factors |
| Job/Main Stat/Stat Prop. Damage | Attribute conversion and eligible attacks | Job irrelevant to isolated confirmed Attack factor; necessary when conversion or skill effects change | No invented conversion. Confirm affected aggregate or obtain verified conversion; item lines insufficient |
| Target Defense/penetration/target kind | Defense/conditional monster bucket | Conditional; unchanged identical factor may cancel, changed penetration cannot | Exact target requirements remain unavailable; a generic Boss label is insufficient |
| Skill coefficients/passives | Changed skill-level effect and attack mix | Conditional for unchanged eligible attack; essential for changed skill line | Never translate skill levels into generic weight. Passives reflected in totals must not be added again |
| Cadence, resources, trigger/uptime | Sustained throughput | Essential only to a sustained-DPS claim, and all dependencies must be modeled | Missing data restricts output to supported factor/per-attack scope, not Low-confidence invented DPS |
| HP/Defense/Evasion/surplus Accuracy | Conditional survival/hit/resource exceptions | No default hidden offensive weight under adequate survival/landing assumption | Preserve raw values; exceptional skill/context dependencies need explicit evidence |

No OCR engine is implemented or benchmarked here; reliability of extraction for any field is unmeasured. Known screenshot labels are not evidence that every required total appears in an equipment comparison. Artifacts/temporary effects already inside confirmed totals are included once; changed conditional effects, cadence or resources must be modeled separately or block the stronger claim. Leaving Chapter Breakthrough for Henesys is not established to clear every buff/passive/trigger; verify actual effect state and stable repeated readings instead of promising a guaranteed unbuffed snapshot.

## Verification and remaining evidence

`tests/reaggregation.test.mjs` uses nine synthetic test groups for source ordering/replacement, exact FD inverse, remaining-cap/nonunit caps, inverse ambiguity, identity/finite errors, tiny-rate precision, neutral/swapped values, claim metadata and source-reference closure. These establish consistency with selected algebra and reference integrity, not game prediction. Independent QA owns additional invariants. Real player data is not used.

Still needed: game rounding/display precision and exact source attachment; job attribute conversions; complete named-context formulas; critical/range/accuracy laws and exceptions; skill/passive/cadence/artifact/uptime data; controlled held-out observations. A useful minimal empirical task later is one supported changed source, unchanged preset/target/effects, current aggregate plus known old/new source units, and repeated ordinary damage observations with timing. The exact collection task must follow the supported profile; CP agreement cannot substitute.
